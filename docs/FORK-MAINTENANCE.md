# Fork Maintenance

This distribution tracks `chattocorp/chatto` (`upstream`) and adds features that
upstream does not ship. This file records what makes upstream merges cheap or
expensive, so the next catch-up does not have to rediscover it.

It does not define the sync procedure. The `chatto-sync-upstream` skill owns the
ordered `upstream -> main -> production -> main-native -> Windows nightly`
contract and its approval gates; follow that skill and treat this file as the
supporting detail on what tends to break along the way.

## The Shape Of The Divergence

Measured against `upstream/main`, the fork is overwhelmingly additive: roughly
240 files that upstream does not have at all, against roughly 250 files modified
in place. Only the second group can conflict.

Keeping that ratio is the single most effective thing we do. When a fork feature
needs to live inside an upstream-owned file, put the logic in a new fork-owned
module and leave one-line call sites behind. `state/server/nativeOrigins.ts` is
the worked example: the desktop origin-lease bookkeeping used to sit inside
`registry.svelte.ts`, which upstream restructures regularly, and it conflicted
in consecutive merges. Extracted, the same behaviour costs four call lines that
`git merge` re-seats on its own.

## Recurring Conflict Hot Spots

These files conflicted in both of the last two catch-ups. Expect them again.

| File | Why |

| `state/server/registry.svelte.ts` | Fork holds native-host origin leases; upstream keeps restructuring the registry. |
| `state/server/store.svelte.ts` | Fork mirrors the custom-emoji and soundboard catalogues off the projection. |
| `auth/reauth.ts` | Fork adds the native OAuth path through the same functions upstream edits. |

## Regenerate, Never Hand-Merge

These are build outputs that happen to be tracked. Resolving them by hand
produces plausible-looking files that do not match what the generator emits.

| Path | Regenerate with |
| --- | --- |
| `cli/internal/pb/**`, `packages/api-types/src/**`, `apps/docs-website/src/generated/**` | `mise run codegen-proto` |
| `apps/frontend/src/lib/i18n/messages.ts` | `pnpm run paraglide` (it is generated by `scripts/generate-i18n-facade.mjs`) |
| `apps/frontend/src/lib/paraglide/**` | `pnpm run paraglide` |
| `pnpm-lock.yaml` | `pnpm install` |

`mise run codegen-proto` deletes `packages/api-types/dist` and
`packages/api-types/src/chatto` before regenerating. Follow it with
`mise run build-api-types`, or the frontend typecheck reports hundreds of
missing-module errors.

## Traps Worth Remembering

- **Two desktop apps.** `apps/desktop/` is upstream's experimental Deno + CEF
  client and is **Apache-2.0**; `apps/desktop-tauri/` is this fork's Windows
  client and is **AGPL-3.0-or-later**. They were briefly the same directory,
  which silently relicensed the Tauri client, because upstream's `REUSE.toml`
  declares `apps/desktop/**` Apache-2.0 and the fork had no entry of its own.
  Keep `mise license-check` in the merge checklist, and treat any upstream diff
  landing in `apps/desktop/` as CEF work until proven otherwise.
- **`rerere` does not replay non-conflicted edits.** Replaying a merge only
  restores files that actually conflicted. Edits made to cleanly-merged files
  during the original resolution are silently dropped. Diff a replayed merge
  against the original before trusting it.
- **Path sweeps miss escaped and space-delimited forms.** Renaming
  `apps/desktop` → `apps/desktop-tauri` left `pnpm --dir apps/desktop tauri
  build` in a PowerShell release script, and the test asserting that exact
  string was rewritten by the same sweep — so the suite stayed green across a
  broken Windows release build. Sweep with a boundary pattern
  (`apps/desktop([^/a-z-]|$)`) and read the remaining hits.
- **Upstream's protobuf tag space is not ours.** A fork-only field on a low tag
  in an upstream-owned message collides the moment upstream adds a field there,
  and upstream does not always reserve tags it vacates. Number fork-only fields
  from 1000 up; `GetServerResponse.compatibility` is the worked example.
- **Upstream test files can encode fork-invalid assumptions.** New upstream
  specs mock only what upstream's components read. When a fork feature adds a
  read (a protocol capability, a store field), those specs fail on `undefined`
  rather than on an assertion. The fix belongs in the mock, not the component.

## Habits Worth Keeping

The `chatto-sync-upstream` skill defines the procedure. These are the things
that are easy to skip and expensive to skip:

- **Prefer upstream's structure and re-seat the fork's behaviour into it.**
  Preserving the fork's shape by reverting upstream turns one merge into a
  permanent conflict.
- **Review with `git show --cc <merge>`.** The combined diff shows only the true
  resolutions and hides everything git merged cleanly, which is the only
  practical way to review a merge this size.
- **Merge `origin/main` once, at the end.** Merging it opportunistically every
  time a fork PR lands produces a merge commit per landing and buys nothing;
  the conflicts are the same whenever they are resolved.
- **Never trust a replayed merge — diff it.** If a merge is ever rebuilt, assert
  the final tree against the verified original (`git diff <verified> HEAD` must
  be empty) before pushing. Rebuilding this fork's catch-up silently dropped
  fourteen files that `rerere` had no record of, including one already known to
  have been lost the same way once before. The tree comparison is the only
  check that catches it.
